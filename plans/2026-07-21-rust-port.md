# tsmanager → Rust port — Plan

Porting [`references/tsmanager`](../references/tsmanager) (Node/Electron) to Rust,
**most-basic-feature-first**, as a series of vertical slices. This document is the
single source of truth: roadmap, decision log (ADRs), and glossary.

Reference (do **not** ship): the JS source in `references/tsmanager/` is the
behavioural spec. When a Rust phase is ambiguous, the corresponding JS module is
the tiebreaker.

---

## 1. What we're building

A lean, single-binary desktop app that manages SSH hosts and what runs on them —
**Console / tmux**, background **managers** (docker, ports, processes), a **Files**
browser, per-host **port forwarding**, and a server-side **Browser** (SOCKS proxy
+ Chrome). It drives the **system `ssh` binary** through a PTY, so `~/.ssh/config`,
keys, agent, and ProxyJump all work as-is.

**Explicitly out of scope:** the plugin host (`plugins.js`, backends, dynamic JS
loading), the bundled Notes/Jira plugins, the shared AI client (`ai.js`), and
`pm2` / GNU `screen` support.

---

## 2. Architecture at a glance

```
workspace/
  core/          Rust — axum server: REST + WebSocket + static file serving
    src/
      main.rs        bootstrap, router, graceful shutdown
      ssh.rs         arg building, ControlMaster, ssh -G, password injection
      pty.rs         portable-pty spawn + reader-thread → mpsc bridge
      ws.rs          WebSocket ↔ PTY glue (console/tmux/logs/exec modes)
      discovery.rs   ~/.ssh/config enumeration + `ssh -G` resolution
      secrets.rs     SecretStore: keyring primary, AES-256-GCM file fallback
      store.rs       per-alias app state (hidden flag, socks index, hasPassword)
      managers.rs    overview / docker / ports / processes  (ssh.exec + parse)
      files.rs       list / stat / preview / download (rsync→scp)
      forward.rs     ssh -L lifecycle
      browser.rs     ssh -D SOCKS + Chrome launch (macOS)
      security.rs    origin guard, loopback bind, SAFE_NAME, shell quoting
  web/           Svelte + TS + Vite — SPA, built to static assets core serves
  desktop/       Tauri wrapper (added in Phase 7)
```

- **Runtime:** `tokio` + `axum`. Serve now with `cargo run -p core`
  (`http://127.0.0.1:7070`); wrap in Tauri in Phase 7.
- **Frontend:** Svelte SPA, `vite build` → static dir served by `tower-http`
  `ServeDir`; xterm.js embedded directly (no wrapper lib).
- **PTY:** `portable-pty`; each session gets a blocking reader thread forwarding
  bytes into a `tokio::mpsc` the WS task drains. The reader thread also hosts the
  password-prompt scan (Phase 2).
- **Server source of truth:** `~/.ssh/config` (live). The app stores only what ssh
  config can't hold, keyed by Host alias.

## 3. Roadmap (dependency-ordered; each rung needs only the rungs below)

> **Status: all phases implemented ✅** (P0–P7). Workspace: `core` (lib `ismcore`
> + bin `core`), `web` (Svelte build), `desktop` (Tauri v2). 25 unit tests + a
> hermetic integration suite (fake `ssh`/`docker`/`ss`/`ps`/`find`, `nc`
> listeners) pass. Caveats: the ssh/manager paths are proven against fakes (no
> local sshd); GNU-only commands (`find -printf`, `ss`, `free`) need a Linux
> host, so macOS `__local__` shows partial data; the Tauri GUI window can't be
> visually verified headlessly (embedded server proven live in-process) and
> `.app`/`.dmg` packaging via `cargo tauri build` hasn't been run.

### Phase 0 — Walking skeleton
Prove the whole toolchain end-to-end before any feature.
- Cargo workspace (`core`, `web`); `desktop` stubbed for later.
- axum serves the Svelte build + `GET /api/health`; a trivial WS **echo** at `/ws`.
- Svelte app boots, hits `/api/health`, opens the echo socket.
- **Done when:** `cargo run -p core` serves the UI and the echo round-trips.

### Phase 1 — Local Console  ← *most basic real feature*
WS ↔ **local** PTY. No SSH, no secrets, no config.
- `pty.rs`: spawn `$SHELL` via `portable-pty`; reader-thread→mpsc bridge.
- `ws.rs`: `mode=local`; forward bytes both ways; handle resize (`{t:'r',cols,rows}`).
- Svelte: xterm.js + fit addon in `onMount`; wire keystrokes/resize to the socket.
- **Done when:** a real local shell works in the browser terminal, resizes cleanly.

### Phase 2 — SSH manager + SSH Console + tmux
Reuse the Phase 1 bridge, but spawn `ssh` instead of a local shell.
- `ssh.rs::ssh_args`: `ControlMaster=auto`, `ControlPath=<tmp>/tsm-<pid>-<alias>.ctl`,
  `ControlPersist`, `ServerAliveInterval=30`, `-tt` for interactive; **connect by
  alias** (`ssh <alias>`) and let ssh resolve options from config.
- Password injection: reader-thread scans output for `password:|passphrase:`,
  injects the stored password once, then detaches (MOTD-safe).
- `mode=tmux` → `tmux new-session -A -s <session>` (attach-or-create).
- Drive it with a hand-picked known alias for now (discovery is Phase 3).
- **Done when:** Console + tmux work over ssh to a real host, incl. a password host.

### Phase 3 — SSH config discovery + secret store
Turn "one known alias" into the live server list.
- `discovery.rs`: parse `~/.ssh/config` for concrete `Host` aliases (skip
  wildcard/pattern entries); run **`ssh -G <alias>`** per host to resolve
  `hostname`/`user`/`port` for display. `ssh -G` uses ssh's own parser → handles
  `Include`, `Match`, tokens for free.
- `secrets.rs`: `SecretStore` — `keyring` primary (macOS Keychain / Secret Service),
  **AES-256-GCM file fallback** (0600 key file) when no backend. Always encrypted
  at rest. Holds optional per-alias SSH passwords under `pw:<alias>`.
- `store.rs`: per-alias app state — `hidden` flag, deterministic socks index,
  `hasPassword`. Sidebar lists non-hidden aliases; hide toggle for git/jump hosts.
- `security.rs`: bind `127.0.0.1` only; origin guard rejects non-loopback origins.
- Include the **local machine** as a pseudo-host (`__local__`) so Phase 1 stays in the list.
- **Done when:** sidebar auto-populates from ssh config; passwords stored encrypted;
  hidden hosts stay hidden.

### Phase 4 — Managers  (drop `pm2` + `screen`)
Read/action commands over the shared connection.
- `ssh.rs::exec`: `tokio::process::Command`, `BatchMode=yes`, reuse ControlMaster
  (fails fast instead of hanging on a prompt).
- Endpoints + Svelte panels: **overview** (host/os/uptime/load/mem/disk),
  **docker** (`ps -a` + `stats`, actions start/stop/restart/rm, `SAFE_NAME`-gated),
  **ports** (`ss`/`netstat` parse, collapse v4/v6 dupes), **processes** (`ps`,
  sorted by cpu; kill by pid).
- WS modes reusing Phase 2: `docker-logs` (`docker logs -f`), `docker-exec`
  (`docker exec -it … bash||sh`).
- **Done when:** all four panels render live data and actions succeed; parsers unit-tested.

### Phase 5 — Files
- `files.rs`: `list` (NUL-delimited `find -maxdepth 1`), `stat` (type/size/mime),
  text preview (≤512 KB, ext/mime allowlist) + image preview (≤4 MB), **download**
  via `rsync` when present, else `scp`; `local` uses the fs directly.
- Svelte: tree browser, text/image preview pane, file/folder download.
- **Done when:** browse → preview → download works local and remote.

### Phase 6 — Port forwarding + Browser  *(Browser = highest risk; spike first)*
- **Spike (do before the phase):** prove on macOS — open `ssh -D 127.0.0.1:<port>`,
  launch Chrome with `--proxy-server=socks5://…`, isolated `--user-data-dir`, and
  confirm the browser sees the server's network. Nail the macOS Chrome launch
  (`open -a "Google Chrome" --args …` vs direct binary) here.
- `forward.rs`: `ssh -N -L 127.0.0.1:<local>:127.0.0.1:<remote>`; probe local port
  for readiness (8 s deadline); track lifecycle; prefer same port, fall back to offset.
- `browser.rs`: per-host SOCKS proxy (`socksBasePort + index`, reused if alive),
  `ssh -N -D`; launch Chrome, isolated profile `$TMPDIR/tsm-browser-<alias>`.
- **Done when:** forward a remote port to localhost; open a server-side Browser that
  reaches the host's `127.0.0.1:PORT`.

### Phase 7 — Desktop wrap
- `desktop/`: Tauri shell; bundle the Svelte build; start `core` in-process on a
  random loopback port; open a window.
- Confirm `keyring` uses macOS Keychain under Tauri's app identity.
- Package `.app`/`.dmg` (macOS). Add `.deb` for Linux as a follow-up.
- Graceful shutdown tears down ControlMaster masters + SOCKS/forward procs.
- **Done when:** a double-click app runs the full feature set; secrets in Keychain.

## 4. Cross-cutting concerns

- **Security:** loopback-only bind; origin guard (loopback origins only); `SAFE_NAME`
  (`^[A-Za-z0-9][A-Za-z0-9_.-]*$`) on every user-supplied name reaching a shell;
  `shell_quote` for anything interpolated into a remote command; passwords never
  returned to the UI (only `hasPassword`).
- **Testing:** unit tests on the pure functions where port bugs hide — `shell_quote`,
  `SAFE_NAME`, origin guard, and the `ss`/`netstat`/`docker json`/`ps` parsers.
  (Mirrors `references/tsmanager/test/safety.test.js` + `files.test.js`.)
- **Platform isolation:** the only two OS-specific spots — Chrome launch and keychain
  backend — live behind small helpers so Linux stays a cheap second target.
- **State location:** per-user data dir (`~/Library/Application Support/<app>/` on
  macOS) so config/secrets survive version upgrades.

## 5. Decision log (ADRs)

| # | Decision | Rationale |
|---|----------|-----------|
| 001 | **Cargo workspace: `core` (axum) first, `desktop` (Tauri) last** | Get a runnable/testable server now; add desktop packaging at the end. Mirrors tsmanager's serve-vs-start duality. |
| 002 | **Full rewrite: Rust backend + TypeScript frontend** | Rust where the real logic + leanness live; full-Rust/WASM UI rejected — no perceived-speed gain for an I/O-bound app, slower terminal hot path (JS↔WASM byte marshaling), slower iteration. |
| 003 | **Svelte + TS + Vite** | Least boilerplate, smallest runtime, best Tauri DX, xterm.js embeds natively; app is many small stateful panels, not one data-grid. |
| 004 | **8-phase, dependency-ordered roadmap, start at P0 skeleton** | "Most basic feature first"; de-risk the Rust+Tauri+Svelte plumbing cheaply before real features. |
| 005 | **`portable-pty` + reader-thread → mpsc → WS bridge** | Most-proven Rust PTY crate, cross-platform (keeps macOS/Windows open); bridge thread is ~15 lines and also hosts password-injection scan. `pty-process` (async, Unix-only) rejected to avoid closing the cross-platform door. |
| 006 | **macOS-first; Linux supported 2nd; Windows parked** | Fastest iteration on the dev machine; Linux cheap via two isolated helpers; Windows real cost with no signal it's needed. |
| 007 | **Server list sourced live from `~/.ssh/config` (Model A)** | Config already describes hosts (tsmanager reuses it anyway); no duplicate registry to drift. Connect by alias → deletes most `sshOptions` machinery. App store holds only ssh-config-can't: optional password, socks index, hidden flag. No `servers.json`, no migration/import. |
| 008 | **Drop `pm2` + GNU `screen`; Browser is must-have** | User doesn't use pm2/screen — trims Phase 4. Browser kept, de-risked with an early macOS SOCKS+Chrome spike. |
| 009 | **SecretStore: `keyring` primary + AES-256-GCM file fallback** | Real OS-Keychain protection on macOS from Phase 1 (works for plain binaries); AES fallback keeps Linux/headless/CI working; one abstraction, two backends. `keyring`-only too brittle; AES-only needlessly delays keychain on the primary platform. |
| 010 | **Discovery via parse-for-aliases + `ssh -G <alias>`** | Enumerate concrete Host aliases (skip wildcards), then let ssh's own parser resolve effective config — handles `Include`/`Match`/tokens without reimplementing the grammar. |

## 6. Glossary

- **Alias / Host alias** — a `Host` name in `~/.ssh/config`; the app's stable server
  `id` and SOCKS-index key. Connecting = `ssh <alias>`.
- **`ssh -G <alias>`** — ssh's "dump effective config" mode; resolves
  hostname/user/port/proxyjump/identityfile using ssh's own parser.
- **ControlMaster / ControlPath / ControlPersist** — SSH connection multiplexing: one
  authenticated master connection per host, shared (via a unix socket at
  `ControlPath`) by Console, tmux, exec, forwards, and the SOCKS proxy. Authenticate
  once (Console), reuse everywhere with no re-prompt.
- **PTY (pseudo-terminal)** — what `portable-pty` gives us so `ssh`/shells behave as
  if attached to a real terminal (password prompts, full-screen apps like tmux).
- **Reader-thread bridge** — blocking OS thread reading PTY output into a
  `tokio::mpsc` channel the async WS task drains (portable-pty is not async).
- **Password injection** — reader-thread watches PTY output for a password/passphrase
  prompt and writes the stored password once, then detaches. Replaces `sshpass`;
  password never touches argv/another process's environ.
- **WS modes** — the `mode` query param on `/ws`: `local`, `console`, `tmux`,
  `docker-logs`, `docker-exec`. Each maps to a command run in the PTY.
- **SOCKS proxy / Browser** — per-host `ssh -D` dynamic proxy; a dedicated Chrome
  profile points at it so the browser sees the network *as the server does*
  (including the server's own `127.0.0.1:PORT`).
- **Port forward** — `ssh -L 127.0.0.1:<local>:127.0.0.1:<remote>`; makes a
  server-local service reachable on localhost.
- **SecretStore** — encrypted-at-rest key/value: `keyring` (OS keychain) when
  available, else AES-256-GCM file. Holds SSH passwords.
- **`__local__`** — the pseudo-host representing the machine running the app; its
  commands run locally instead of over ssh.
- **`SAFE_NAME`** — `^[A-Za-z0-9][A-Za-z0-9_.-]*$`; validates any user name that
  reaches a shell (container ids, session names, etc.).

## 7. Open items / risks

- **Browser on macOS** — the one feature with real porting unknowns; the Phase 6
  spike must land before committing the phase. Chrome launch flags + isolated
  profile are the risk.
- **Password hosts** — verify password injection timing against a real password-auth
  host early in Phase 2 (prompt patterns vary).
- **`ssh -G` cost** — resolving every alias on load could be slow for large configs;
  cache results, refresh on demand.
- **`keyring` under plain binary vs Tauri** — confirm the same Keychain entries are
  reachable before *and* after the Phase 7 wrap (app identity can differ).
